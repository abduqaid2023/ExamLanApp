# ExamLanApp - نظام اختبارات عبر شبكة محلية (LAN)

## 📱 طريقة البناء من الهاتف فقط (بدون كمبيوتر) - عبر GitHub Actions

المشروع جاهز بالكامل (كل ملفات Gradle موجودة) ومهيأ للبناء التلقائي في السحابة. اتبع هذي الخطوات من هاتفك:

### 1) أنشئ حساب واستودعاً (Repository) على GitHub
- نزّل تطبيق **GitHub** من متجر Play (أو استخدم المتصفح على m.github.com)
- سجّل حساب جديد إذا ما عندك واحد
- أنشئ Repository جديد، خله **Public** أو **Private** (كلاهما يدعم GitHub Actions مجاناً)
- سمّه مثلاً: `ExamLanApp`

### 2) ارفع ملفات المشروع
أسهل طريقة من الهاتف:
- افتح تطبيق GitHub → ادخل الـ Repository → **Add file → Upload files**
- فك ضغط ملف `ExamLanApp.zip` أولاً باستخدام أي تطبيق فك ضغط (مثل ZArchiver من متجر Play)
- ارفع كل الملفات والمجلدات (حافظ على نفس بنية المجلدات كما هي)

> ⚠️ تطبيق GitHub الرسمي أحياناً لا يدعم رفع مجلدات متعددة المستويات بسهولة. البديل الأضمن: استخدم متصفح الهاتف (Chrome) وادخل على `github.com` بوضع "Desktop site"، فهناك خيار "Add file → Upload files" يدعم رفع الملفات، أو ارفع الملفات مجلد-مجلد بالترتيب.

### 3) شغّل البناء التلقائي
- بمجرد ما ترفع الملفات لفرع `main`، سيبدأ GitHub تلقائياً بتشغيل ملف `.github/workflows/build.yml`
- من تطبيق/موقع GitHub: ادخل تبويب **Actions** في الـ Repository → شوف حالة البناء (Build APK)
- البناء يأخذ عادة 3-6 دقائق

### 4) نزّل ملف APK الجاهز
- بعد اكتمال البناء بنجاح (علامة ✅ خضراء)، ادخل على تفاصيل التشغيل (Run) → قسم **Artifacts** بالأسفل
- اضغط على `ExamLanApp-debug-apk` لتنزيله (يأتي كملف zip يحتوي الـ APK بداخله)
- فك الضغط، وثبّت `app-debug.apk` مباشرة على هاتفك (فعّل "السماح بالتثبيت من مصادر غير معروفة" إذا طلب منك)

### ملاحظة عند فشل البناء
لو ظهر خطأ أحمر ❌ في Actions، افتح السجل (Log) وابعث لي نص الخطأ، وأنا أساعدك تحله فوراً - أغلب الأخطاء تكون بسبب ملف ناقص أو خطأ نسخ بسيط.

## 💻 طريقة الإعداد التقليدية (لو توفر لك كمبيوتر لاحقاً)
1. افتح Android Studio → **Open** → اختر مجلد `ExamLanApp` مباشرة (المشروع جاهز بالكامل، لا حاجة لإنشاء مشروع جديد)
2. Sync Gradle ثم شغّل التطبيق مباشرة على المحاكي أو جهاز حقيقي

## كيف يعمل النظام عملياً
- **الأستاذ**: يفتح التطبيق → "وضع الأستاذ" → ينشئ الاختبار → يضغط "بدء استقبال الطلاب".
  عندها يبدأ خادم مدمج على المنفذ `8080` داخل هاتف/جهاز الأستاذ نفسه.
- **الأستاذ يحتاج معرفة IP جهازه**: إعدادات الهاتف → Wi-Fi → تفاصيل الشبكة المتصل بها (أو الهوت-سبوت).
- **الطالب**: يتصل بنفس الشبكة (هوت-سبوت الأستاذ أو الراوتر) → يفتح التطبيق → "وضع الطالب" → يدخل IP الأستاذ + اسمه ورقمه → "الاتصال وجلب الاختبار".
- الطالب يجاوب، وكل إجابة تُحفظ محلياً بشكل دائم فوراً (حتى لو انطفأ التطبيق).
- عند الضغط على "رفع الإجابة النهائية"، تُرسل الإجابات لجهاز الأستاذ وتُحفظ هناك بشكل دائم أيضاً.
- الأستاذ يشوف كل الإجابات الواردة لحظياً، ويضع الدرجة لكل طالب، وتُحفظ في قاعدة البيانات (كشف الدرجات).

## نقاط مهمة للتوسعة اللاحقة
- **تصدير كشف الدرجات**: أضفت مكتبة Apache POI في Gradle - أقدر أكتب لك دالة تصدّر جدول `submissions` المصحح إلى ملف Excel/CSV.
- **دعم 50 طالب دفعة واحدة**: Ktor + CIO engine يدعم هذا العدد بسهولة على شبكة محلية عادية.
- **منع الغش/تعدد الأجهزة**: يمكن ربط `studentId` بجهاز واحد فقط، أو منع إعادة الإرسال بعد النجاح.
- **مؤقّت الاختبار (Countdown)**: يوجد حقل `durationMinutes` جاهز في نموذج `Exam` - يحتاج فقط عداد تنازلي في واجهة الطالب يرفع تلقائياً عند انتهاء الوقت.
- **شاشة إنشاء أسئلة ديناميكية**: حالياً الأسئلة مكتوبة كمثال ثابت بالكود - أقدر أبني لك شاشة كاملة لإضافة/حذف أسئلة بصرياً.

## بنية الملفات
```
data/Models.kt          -> نماذج الاختبار والإجابات + كيانات Room
data/db/AppDatabase.kt  -> قاعدة البيانات والحفظ الدائم
network/TeacherServer.kt-> الخادم المحلي (عند الأستاذ)
network/StudentClient.kt-> الاتصال بالخادم (عند الطالب)
viewmodel/              -> منطق العمل لكل وضع
ui/                     -> واجهات Compose
MainActivity.kt         -> نقطة الدخول واختيار الوضع
```
